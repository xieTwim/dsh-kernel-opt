# 已知边界

按「会不会让你读错面板」排序。

## 信任相关

- **信任链以会话日志完整性为前提。** 它成立靠「写权限限制在 workspace 内 + 日志存放在 workspace 外」这对组合。若把会话 workspace 圈到 `~/.dsh` 或其上层（agent 因而能改写自己的日志），来源／复测的一切结论不再适用。
- **自报点可被伪造。** 防线是来源命令行明牌 + 监督 + finalize 复测，不是不可伪造性。
- **幻影点。** 契约行按「行首前缀」识别。纯读取命令与返回存档文本的工具的输出不计点，但**文档或脚本里整行写出契约、又被真程序打印出来**仍会产生点；引用契约时写在句中即可避免。

## 测量相关

- **一次评测一个点。** 契约行按 payload 逐字在整个会话内去重。代价：两次独立评测若逐位相同（连 metrics 一起）只留一个点——实测中重测参考与实例抖动总会让某一位不同，而把捞回来的行算两遍会同时污染曲线与预算。细节见 [`eval-contract.md`](eval-contract.md#一次评测一个点)。
- **分母漂移只能报，不能修。** 面板能改用汇总分母重算曲线，但表格里逐行自报的比值是评测器的原话，照录。见 [`eval-contract.md`](eval-contract.md#分母漂移只能报不能修)。
- **profiler 的 ▲ 认不出跑在别处的 profiler。** 检测按本机 shell 命令行的可执行 token 匹配，所以 `ssh box 'ncu …'` 认得出，而 `modal run app.py::profile`、`sbatch job.sh` 这类把命令封进脚本再投出去的形态认不出。实测：一轮 Modal run 真跑了 3 次 ncu 并在总结里给出 DRAM 66%／MemBusy 39.5%，面板 ▲ 是 0。**「没有 ▲」是弱证据**，profile 的内容仍只能走 `native_metrics`。
- **复测的执行环境。** finalize 复测以会话工作目录为 cwd、以 dsh 服务进程 env 运行：包装脚本 env 自包含（persona 有要求）时可靠。命令超过 300 字符会因投影截断而跳过复测（面板如实标注「未复测」）。
- **解析不了就不成点。** 评测结果必须能按两种形态之一解析；纯文本工具结果显示为「未测得」行。

## 面板相关

- **只覆盖内存中的会话**（`ctx.sessions`）：dsh 重启后旧会话在被重新载入前查不到序列。
- **Tab 的按需出现由 client watcher 轮询判定**（会话切换／首个信号后 ≤3s 出现）。
- **kernel 源码本体不进面板**（结构化 `write`／`edit` 改动在展开行里可见；完整源码在你的工作区与 git 历史里）。
- **`self_compact` 的压缩范围由官方 compaction backend 决定。**
